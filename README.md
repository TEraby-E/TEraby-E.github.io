# Terabyte 主页与学习手账

学习打卡程序位于个人网站的独立 `study/` 页面。主页保留学习资源、社交链接与素材，不显示学习手账跳转模块。网站全部使用静态 HTML、CSS 和 JavaScript，部署后不需要启动 Python、本地服务或 OneNote。

打卡界面的主标题为“饮水思源 · 爱国荣校”，下方为“不要把梦想埋没”。Terabyte 的数据流标志以共用竖干的 T、B 与输入数据块组成，矢量源文件位于 `Assets/Icons/terabyte-flow.svg`；页眉、页脚与浏览器图标已统一使用这个标志。

发布后的入口：

- 个人主页：<https://terabyte.top/>
- 学习手账：<https://terabyte.top/study/>

正式域名沿用 `CNAME` 中的 `terabyte.top`。页面更新以 GitHub Pages 的部署结果为准。

## 发布到现有 GitHub Pages

如果仓库已经通过 **Deploy from a branch** 发布，可保留现有分支与根目录发布设置。将本次文件提交并推送到该发布分支后，主页和 `study/` 会一同更新，无需更换域名或重建网站。

也可以使用项目提供的 Actions 工作流，只需配置一次：

1. 在仓库 **Settings → Pages → Build and deployment** 中，把 **Source** 设为 **GitHub Actions**。
2. 打开 **Actions → Deploy homepage and study check-in → Run workflow**，选择发布分支并运行。
3. 等待检查和部署成功，打开部署结果给出的实际网址。之后推送 `main` 或 `master` 会自动更新。

工作流先运行 `npm test`，再将 `index.html`、`style.css`、`CNAME`、`Assets/`、`study/` 和 `.nojekyll` 组装到 `_site/` 发布，不上传整个仓库根目录。开发测试、Git 元数据和个人迁移备份不会进入该发布包。发布方式依据 [GitHub Pages 自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 每天使用

直接打开 <https://terabyte.top/study/> 使用学习手账，也可以收藏该网址。主界面只显示当天任务，任务库和历史记录在点击后打开。

1. 点击英语、高数、线代、概率论、数据结构、计组、操作系统或计网，按章节自由组合学习任务。
   学科名称旁的“>”箭头按钮独立控制整科学习卡展开或收起，展开时朝下；学科名称仍用于选择任务。学习备注默认展开，也可手动折叠。页面不显示原表行号等出处信息。
2. 点击学科名称打开任务选择窗口；学完后使用任务卡的打卡按钮或逐项勾选。实际分钟数默认读取任务原有的内部预计值，缺少默认值时留空；用户可以修改，修改单日任务时保留已记录的实际值。保存后才标记完成，取消弹窗不会打卡。
   “标记完成”仅用于多日任务，并放在打卡弹窗中；任务选择窗口不提供独立完成按钮。多日任务可以一天记录多段，每次填写本次实际分钟数并累加，勾选“标记完成”才结束整项任务。
   今日清单默认收起各科学习卡，使用学科旁的“>”展开；该学科所有任务共用一个折叠区，不再嵌套“已完成”框。任务库中的已完成章节和任务继续折叠收纳。
   只有当天安排了任务的学科才在收起时显示阶段进度和今日实际用时。阶段进度 = 当前阶段已完成任务的预计用时之和 ÷ 当前阶段任务的预计总用时；采用学习记录中的累计完成状态，多日任务需明确标记完成后才计入。共享任务去重，缺少预计用时的任务不估算，比例标注为“已知用时”。阶段跟随任务选择窗口的阶段设置。
   “选择学习任务”窗口在搜索栏下方始终显示当前学科阶段进度，与主页共用计算和展示组件；切换阶段会更新，搜索和临时勾选不改变进度分母，未添加今日任务时也能查看。
3. 点击 **导出今日图片**，保存当天清单及实际用时。
4. 点击 **保存并进入下一天**，当天内容进入历史；未完成任务可以选择带到下一天。
5. 临时增加的学习内容可以用 **自定义打卡** 记录。选所属学科，填写内容和实际分钟数，可附备注。保存后直接计入当天用时，随当天归档。登录时，这条记录也会同步到同一账号的其他设备。

## 实际学习时长

学习日期左边只显示当天实际学习时长，根据已记录的打卡分钟数自动汇总；共享原任务按同一来源去重，缺少实际用时不会用原预计值补算。

不显示每日预计用时总量，不提供预计时间修改弹窗；任务原计划值用于打卡实际输入框的默认值和学科阶段进度的权重。当天实际用时仍独立根据打卡记录统计。

同一份整卷或综合复盘被分到多个学科时，合计只计一次共享时间，避免重复相加。每日时间调整会随归档及 JSON 备份保存。

点击单日任务的“已打卡”可修改实际用时；点击多日任务的“继续打卡”记录下一段，本次时间由用户填写，并累加到当天。弹窗列出当天片段，支持撤销最后一段；完成状态可以重新开放，已记录用时保留。共享条目记录一段时仅累计一次。

408 可选任务库已移除标题含“王道书”的阅读卡，其他视频、练习与综合题保留。以前保存的相关清单、历史与备份仍然可读，这些退役条目不会再出现在新任务选项中。

任务和完成状态会自动保存。未登录时使用当前浏览器的记录。配置并登录云端同步后，同一账号可在不同设备上查看今日清单、实际用时和归档历史。Chrome、Edge 等浏览器支持时，可以将手账安装到桌面或任务栏。首次完整载入并缓存后，本机模式可离线使用，云端模式需要联网读写。

## 配置数据库与账号

### 1. 创建 Supabase 项目

打开 [Supabase 控制台](https://supabase.com/dashboard)，选择 **New project**。填写项目名，例如 `study-journal`，设置数据库密码，等待项目准备完成。数据库密码留在你自己的密码管理器中，学习手账登录会用到下面单独创建的账号。

### 2. 建表并开启实时同步

在项目左侧打开 **SQL Editor → New query**，把 [`supabase/study-journal.sql`](supabase/study-journal.sql) 的全部内容复制进去，点击 **Run**。在 **Table Editor** 中可以看到 `public.study_journals`。

每个账号对应一行。`user_id` 是 Supabase Auth 分配的用户 UUID，`snapshot` 保存当前清单、归档、打卡用时和进度，`revision` 用来防止两台设备互相覆盖。脚本同时配置了行级权限（RLS）与 Realtime 发布，登录用户只能读取和修改自己的记录。项目的 **Integrations → Data API** 中应启用 Data API 并保留 `public` 在可访问的 schema 列表中。如果项目限制了具体表的访问，把 `study_journals` 加进去。[Data API](https://supabase.com/docs/guides/api/creating-routes) · [行级权限](https://supabase.com/docs/guides/database/postgres/row-level-security) · [Realtime](https://supabase.com/docs/guides/realtime/postgres-changes)

### 3. 创建 `terabyte` 账号

在 **Authentication → Sign In / Providers** 中启用 Email 登录，关闭 **Allow new users to sign up** 和 **Allow anonymous sign-ins**。进入 **Authentication → Users → Add user → Create new user**，邮箱填 `terabyte@study.terabyte.top`，密码填你为手账设定的值。勾选 **Auto Confirm User** 后保存。从用户列表复制 Supabase 生成的 **UID**。手账把 `terabyte` 映射到这个登录邮箱。如果需要创建其他账号，可以在同一处添加，其他账号用各自的邮箱登录。[Supabase Auth 设置](https://supabase.com/docs/guides/auth/general-configuration)

### 4. 填写项目地址、公开密钥和自己的用户 UID

点击 Supabase 项目顶部的 **Connect**，复制 **Project URL** 和 **Publishable key**。打开 [`study/cloud-config.js`](study/cloud-config.js)，填入这两项和第 3 步复制的 UID，保留引号。[Supabase API 密钥](https://supabase.com/docs/guides/getting-started/api-keys)

```js
window.STUDY_CLOUD_CONFIG = Object.freeze({
  url: 'https://你的项目标识.supabase.co',
  publishableKey: 'sb_publishable_你的公开密钥',
  ownerUserId: '你的用户 UID',
});
```

网页会公开这三项。`sb_secret_`、`service_role`、数据库密码和账号密码都应留在网页与 Git 仓库之外。所有配置留空时，手账使用本机模式。`ownerUserId` 决定哪个账号会自动迁入旧的浏览器记录。

### 5. 预览、迁移并验证

1. 在仓库根目录运行 `python -m http.server 8767`，打开 [本地手账](http://127.0.0.1:8767/study/)。点右上角的云朵，输入用户名 `terabyte` 和第 3 步设置的密码。验证通过后，按上面的 GitHub Pages 步骤发布。
2. 发布后，在你一直打卡的浏览器中打开[正式手账](https://terabyte.top/study/)，登录第 3 步创建的本人账号。旧记录会自动合并到该账号一次，本机副本仍可在退出后查看。预览地址和正式网址各有独立的本机存储。若旧记录分散在多个浏览器，首次自动迁移后，其余备份可以在 **记录管理** 中手动导入本人账号。
3. 用两台设备或两个独立浏览器配置文件登录同一个账号。一边新增自定义打卡或归档，另一边保持在线打开手账，观察清单与历史是否更新。首次打开账号手账后，可以在 **Table Editor → study_journals** 看到该账号的行，保存后 `revision` 会增加。
4. 在另一个浏览器配置文件或无痕窗口登录第二个账号，确认它只显示自己的清单与历史。同一浏览器的普通标签页共享登录状态。其他账号登录时，只同步各自账号里的内容，旧本机记录等你本人登录后才上传。

如果两边同时保存，先提交的版本会保留，另一边会提示载入最新记录后重做这次操作。断网时页面会提示保存失败，保留当前页面即可在恢复联网后重试。退出登录后，页面会回到该浏览器的本机记录。

登录成功后，会话会保存在当前浏览器并自动续期。刷新或关闭重开同一个网址时会恢复登录。换设备、换浏览器、主动退出、清除网站数据或会话被撤销时，需要重新登录。[Supabase 会话](https://supabase.com/docs/guides/auth/sessions)

## 记录备份与迁移

本机记录保存在当前浏览器的 IndexedDB 中，清除该网址的网站数据会清除本机记录。云端记录存入所配置的 Supabase 项目。进入 **记录管理** 可以导出当前模式的完整备份，导入时会检查格式并合并已有记录。

旧本地程序的迁移备份作为独立文件交付，可在发布后的手账中导入。将个人备份保留在自己的电脑上，不要放进 `study/` 或上传到公开仓库。本项目包含章节任务库，不包含个人打卡数据。

## 图片保存位置

点击 **导出今日图片** 后，浏览器复用当前页面生成 PNG：从校训、今日学习时长和日期开始，右上角单独显示圆形交大校徽，包含八个学科区域，直到完整的底部进度托盘。页面和图片均不显示“今天的任务”、任务数量和自动保存提示。图片保留当前展开／收起状态，不再使用独立的 Canvas 卡片排版或 408 汇总简图；折叠中的任务仍完整保存在学习记录中。历史图片也复用相同页头、卡片与进度布局。

图片以两倍分辨率输出；超长清单会连续分张，优先在卡片边缘断开，特别长的单张卡片也不会丢失文字。普通下载模式下，多张 PNG 会打包为一个 ZIP。截图组件固定为本地 vendored html-to-image 1.11.13（MIT），仅在导出时载入，随离线资源缓存。

归档时保存各学科当天的阶段进度快照，备份和导入会保留；之后完成更多任务或切换阶段不会改变旧图片中的比例。旧记录缺少快照时，只依据截至该日期的归档任务重建，优先使用该日任务所属阶段，不使用未来完成状态。

## 响应与动画

收起的学科只生成摘要，详细卡片首次展开时才创建，重复展开复用已有内容；打卡或任务数据变化后会刷新详情。阶段进度按当前记录缓存，卡片的元数据与备注展示在同次渲染中复用，隐藏卡片不参与位置动画测量。

摘要与详情通过约 300 毫秒的高度过渡和淡入切换，连续点击会从当前高度反向过渡。动画结束后释放临时样式；保存、刷新和导出会先结束切换，避免截到中间状态。系统启用“减少动态效果”时直接切换。

带版本号的任务库复用浏览器缓存，离线安装复用已下载资源；不同版本的资源不会写入当前版本的缓存。查看历史和导出备份使用只读数据库事务，保存与归档继续使用独立写事务。

在支持文件夹选择的 Chrome、Edge 中，可以先在 **记录管理** 选择一次导出文件夹，并选中桌面。浏览器仍保留授权时，之后会直接写入该文件夹；同名文件使用新名称。如果浏览器不支持目录选择，或目录授权已失效，则使用普通下载，保存位置由浏览器下载设置决定。

## 开发验证

不需要 `npm install`，也没有前端编译步骤。安装 Node.js 22 或更高版本后，在仓库根目录运行：

```sh
npm test
```

修改主页时编辑根目录 `index.html` 和 `style.css`；修改打卡程序时编辑 `study/`。任务库在 `study/data/library.json`，不要在该文件中写入个人学习记录。

开发预览可以使用任意静态 HTTP 服务。例如在仓库根目录运行 `python -m http.server 8767`，然后访问 `http://127.0.0.1:8767/` 或 `http://127.0.0.1:8767/study/`。正式使用时打开发布后的固定网址即可。

校徽来自[上海交通大学视觉形象识别系统](https://vi.sjtu.edu.cn/index.php/articles/bulletin/13)。学习任务来自已有资料；手账背景与纸纹为项目内的静态 SVG。

## 多日任务

任务默认是单日任务，高数、线代、概率论的“知识点学习”共 31 项默认设为多日任务。在任务选择界面的“任务类别”中可以随时切换。多日任务的每日打卡只记录当天完成情况和实际用时，不代表整项学习完成；只有手动“标记完成”才结束任务库中的这项任务。保存并进入下一天时，勾选保留未完成任务，会将尚未结束的多日任务带入下一天，并清空新一天的打卡状态及实际用时。任务库和今日清单会显示累计打卡天数。

章节中的全部任务完成后，章节会进入左侧默认折叠的“已完成章节”；取消任意任务的完成状态，该章节会回到未完成区域。多日任务必须显式标记完成才满足章节完成条件。前端采用组合结构：`LearningNode` 父类提供子节点聚合、完成/未完成分组及折叠渲染；`LearningTask` 与 `LearningChapter` 继承父类，今日清单、章节任务及章节导航复用同一套逻辑。

所有八科的今日任务和任务库均使用父类 `LearningNode` 管理完成状态、取消完成、类别切换及每日打卡。父类通过原任务分组同步跨学科条目；各科互不相关的任务不会一起完成。单日任务不提供额外完成标记；只有每日打卡决定其完成状态。旧版标记仍兼容读取。章节状态由子节点自动聚合，不再另写学科分支；多日任务的日常打卡和整项完成依然分开保存。

## 手账卡片布局

卡片显示采用 `TaskCardView` 父类统一标题、任务信息、备注、时间、完成按钮和状态；今日清单、任务库、历史记录分别继承为 `DailyTaskCardView`、`LibraryTaskCardView`、`HistoryTaskCardView`，共用 `LearningNode` 的状态逻辑。卡片样式集中在 `study/cards.css`，手机改为全宽学科区块和上方章节导航。`CardMotion` 统一处理卡片入场、位置变化与折叠过渡，并尊重系统的减少动态效果设置。

设计参考：Day One（https://dayoneapp.com/）的阅读留白、Sunsama（https://www.sunsama.com/）的日计划层级，以及 Zinnia（https://pixiteapps.com/apps/zinnia/）的纸张手账语言；不依赖这些服务或其素材。

全站手账页面及导出图片统一采用 Times New Roman + 宋体混排：拉丁字母、数字及英文标点由 Times New Roman 显示，中文使用宋体；表单控件继承同一字体。

PNG 导出同步手账卡片样式：暖纸卡框、状态徽标、单日/多日类别、当前打卡/整项完成、累计打卡天数及实际用时。通过卡片视图生成导出快照，由 ImageCard 父类与 TaskImageCard、SubjectImageCard 子类绘制；图片展开保留全部当天任务和备注，长清单继续自动分页。标题采用加粗宋体/Times New Roman。

## 性能优化

任务库使用一次建立的 Map 索引，当前状态使用带版本和引用校验的 Set/Map 查询缓存；父类仍负责全部学科的相同完成逻辑。静态任务库在存储模块中冻结并复用，避免每次读取复制整份 JSON。清单按学科局部更新 DOM，选择任务仅更新对应章节计数；搜索采用 90 毫秒合并输入，动画只处理视口附近的卡片，并合并布局测量。离屏卡片启用浏览器原生 content-visibility，导出继续使用完整数据，不受折叠和离屏状态影响。

任务库 JSON 只去除格式空白，校徽复用已有 ICO 的 256 像素原始 PNG 帧，主页背景采用逐像素一致的无损 WebP，像素字体只加载实际使用的下划线字形。离线缓存按版本整体更新，静态资源再次打开时优先读取当前缓存，页面文档继续联网检查更新；JSON、备份和学习记录的格式不变。

本机固定 2,496 项任务查询基准的五次平均：17.68 ms → 2.49 ms，结果校验值保持一致。该数值是任务查询基准，不代表整站加载时间。原始任务库 2,212,243 → 1,470,004 字节；校徽 SVG 405,434 → 85,661 字节；背景图 3,596,926 → 2,430,820 字节；下划线字体 487,364 → 1,628 字节。

修改任务库或静态资源后，同步更新 `study/sw.js` 的 CACHE/RELEASE 及 HTML 的资源版本号。任务库会携带 storage.js 的版本请求；新文档的版本与旧 worker 不匹配时强制走网络，避免首次刷新仍命中旧资源。预缓存也使用发布版本号请求资源。

## 移除预计用时功能
